# Performance sample corpus

Inputs for benchmarking doc2x / xls2x / ppt2x. Two tiers per format.

| File | Tier | Source | License |
|------|------|--------|---------|
| `small/simple.doc` | small | copy of `UnitTests/files/simple.doc` | this repo (LGPL-compatible project fixture) |
| `small/simple.xls` | small | copy of `UnitTests/files/simple.xls` | this repo |
| `small/simple.ppt` | small | `with_textbox.ppt` from the Apache POI / NPOI test data (`testcases/test-data/slideshow`) | Apache-2.0 |
| `large/large.doc` | large (~10 MB) | generated by `generate.py` from `small/simple.doc` | derived from the above |
| `large/large.xls` | large (~10 MB) | generated from `small/simple.xls` | derived |
| `large/large.ppt` | large (~10 MB) | generated from `small/simple.ppt` | derived |

Large files are **not committed** (`large/` is git-ignored). Regenerate and verify:

    python perf/corpus/generate.py            # writes large/*, checks SHA256 vs manifest.json
    python perf/corpus/generate.py --update   # only when the generator/inputs change

`generate.py` (Python 3 stdlib only) re-serialises each small file as an OLE
compound file and adds one stream, `PerfPadding`, of ~10 MB of seeded
pseudo-random bytes (SHA-256 counter mode). Output is byte-identical on every OS;
`manifest.json` holds the expected SHA256 of every file.

Limitation: the padding stream is ignored by the translators, so large files
measure OLE/file I/O and container parsing at scale, not per-paragraph / per-cell /
per-slide scaling of the document content.

Converting: the Shell tools write the output next to the input
(`perf/corpus/large/large.docx`, etc.; outputs are git-ignored).

Known issue (pre-existing): `xls2x` currently fails on `simple.xls` (also on the
original `UnitTests/files/simple.xls`), so xls conversion of both xls tiers fails
until that is fixed.
